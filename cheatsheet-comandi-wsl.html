🚀 AVVIO Dopo riavvio del PC (sequenza completa)
ℹ️ Dopo ogni riavvio Windows/WSL, i container si fermano. Seguire questi 3 step in ordine.
Step 1 – Entra nella cartella del progetto
# Apri il terminale WSL, poi: cd ~/urbreath/superset
Step 2 – Avvia tutto lo stack
# Avvia tutti i container in background docker compose -f docker-compose-v6.yml up -d
✅ Questo avvia DB, Redis, Superset, pgAdmin e il Frontend React in un solo comando. Superset impiega circa 1-2 minuti per completare il db upgrade e init.
Step 3 – Verifica che tutto sia partito
# Controlla lo stato dei container (tutti devono essere "running") docker compose -f docker-compose-v6.yml ps # Health check Superset (attendi "OK" – può richiedere ~2 min) curl -s http://localhost:17789/health
⚡ Comando unico di avvio (copia e incolla diretto)
cd ~/urbreath/superset && docker compose -f docker-compose-v6.yml up -d
ℹ️ Dopo ~2 minuti aprire http://localhost:17789 nel browser Windows.
🛑 STOP Fermare i container
Stop normale (dati conservati)
# Ferma i container, i volumi restano cd ~/urbreath/superset docker compose -f docker-compose-v6.yml down
Stop con rimozione volumi ⚠️
# ATTENZIONE: cancella anche i dati DB! cd ~/urbreath/superset docker compose -f docker-compose-v6.yml down -v
⚠️ down -v rimuove i volumi Docker: perderai i metadati Superset (dashboard, utenti, connessioni DB) e i dati urbreath_dev. Usare solo per un reset completo.
🔄 RESTART Riavviare singoli container
# Riavvia solo Superset (senza toccare DB e Redis) docker restart superset_v6 # Riavvia solo il frontend React docker restart embeddedsuperset_v6 # Riavvia tutto lo stack cd ~/urbreath/superset docker compose -f docker-compose-v6.yml restart
📋 LOG Monitorare i log
# Log in tempo reale di Superset (Ctrl+C per uscire) docker logs superset_v6 --follow # Ultimi 50 righe di log di Superset docker logs superset_v6 --tail 50 # Log del frontend React docker logs embeddedsuperset_v6 --tail 30 # Log di tutti i container insieme cd ~/urbreath/superset docker compose -f docker-compose-v6.yml logs --follow
🔍 STATUS Verificare lo stato
# Stato di tutti i container del compose cd ~/urbreath/superset docker compose -f docker-compose-v6.yml ps # Health check Superset (deve rispondere "OK") curl -s http://localhost:17789/health # Verifica DB metadati Superset docker exec superset-db-v6 pg_isready -U superset # Verifica DB urbreath_dev docker exec external-postgres-v6 pg_isready -U external_user # Lista tutti i container Docker attivi docker ps
🔑 Test login API Superset
# Verifica che le API rispondano (deve restituire access_token) curl -s -X POST http://localhost:17789/api/v1/security/login \ -H "Content-Type: application/json" \ -d '{"username":"admin","password":"admin","provider":"db"}' \ | python3 -m json.tool | grep access_token
🔨 REBUILD Ricostruire le immagini (dopo modifiche ai file)
# Rebuild solo Superset (dopo modifica Dockerfile o superset_config.py) cd ~/urbreath/superset docker compose -f docker-compose-v6.yml build --no-cache superset_v6 docker compose -f docker-compose-v6.yml up -d superset_v6 # Rebuild solo il frontend React (dopo modifiche al codice JSX) docker compose -f docker-compose-v6.yml build --no-cache embeddedsuperset_v6 docker compose -f docker-compose-v6.yml up -d embeddedsuperset_v6
⚛️ EMBEDDED Configurare il Frontend React (App embedded)
ℹ️ Dopo aver importato le dashboard in Superset 6, è necessario recuperare gli UUID e aggiornarli nel file .env.v6, poi ricostruire il container frontend.
Step 1 – Recupera l'UUID di ogni dashboard da Superset

Per ogni dashboard (Madrid, Cluj-Napoca, Tallinn, Leuven):

  1. Apri http://localhost:17789 → Dashboards
  2. Clicca sui tre puntini ⋮ accanto alla dashboard
  3. Seleziona "Embed dashboard"
  4. Abilita l'embedding se non è già attivo (toggle Enable embedding)
  5. Copia l'UUID mostrato (formato: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx)
✅ Alternativamente: apri la dashboard, guarda l'URL del browser. Vedrai /superset/dashboard/<ID>/. Puoi usare l'ID numerico oppure cercare l'UUID via API.
Step 2 – Recupera gli UUID via API (opzione comoda)
# Da terminale WSL – ottieni tutti gli UUID delle dashboard TOKEN=$(curl -s -X POST http://localhost:17789/api/v1/security/login \ -H "Content-Type: application/json" \ -d '{"username":"admin","password":"admin","provider":"db"}' \ | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])") curl -s -H "Authorization: Bearer $TOKEN" \ "http://localhost:17789/api/v1/dashboard/?q=(page_size:20)" \ | python3 -m json.tool | grep -E '"title"|"uuid"'
Step 3 – Aggiorna il file .env.v6

Modifica il file ~/urbreath/superset/.env.v6 sostituendo i PLACEHOLDER con gli UUID reali:

# Apri il file con nano (da WSL) nano ~/urbreath/superset/.env.v6 # Oppure modificalo direttamente con sed (sostituisci gli UUID): # Esempio – sostituisci manualmente i valori PLACEHOLDER: # REACT_APP_DASHBOARD_MADRID=<UUID-madrid> # REACT_APP_DASHBOARD_CLUJ=<UUID-cluj> # REACT_APP_DASHBOARD_TALLINN=<UUID-tallinn> # REACT_APP_DASHBOARD_LEUVEN=<UUID-leuven> # I LINK devono essere solo il path relativo (NON l'URL completo): # REACT_APP_DASHBOARD_MADRID_LINK=/madrid # REACT_APP_DASHBOARD_CLUJ_LINK=/cluj-napoca # REACT_APP_DASHBOARD_TALLINN_LINK=/tallinn # REACT_APP_DASHBOARD_LEUVEN_LINK=/leuven
⚠️ Salva con Ctrl+X → Y → Enter (nano). Il file deve stare in ~/urbreath/superset/.env.v6 (non nella sottocartella urbreath-ds-embedded).
Step 4 – Rebuild e riavvio del frontend embedded
# Rebuild del container frontend (legge .env.v6 al momento del build) cd ~/urbreath/superset docker compose -f docker-compose-v6.yml build --no-cache embeddedsuperset_v6 docker compose -f docker-compose-v6.yml up -d embeddedsuperset_v6 # Verifica che sia partito docker logs embeddedsuperset_v6 --tail 20
✅ Dopo ~30 secondi apri http://localhost:3001/app/ nel browser Windows.

🛠️ Troubleshooting rapido
Superset non risponde su http://localhost:17789
# Controlla se il container è in esecuzione docker ps | grep superset_v6 # Leggi gli ultimi errori nei log docker logs superset_v6 --tail 30
Errore "yaml: invalid UTF-8" su docker compose
# Il file docker-compose-v6.yml ha caratteri non-ASCII (emoji nei commenti) # Verificare con: file ~/urbreath/superset/docker-compose-v6.yml # Se non è UTF-8, riscrivere il file senza emoji nei commenti YAML
Superset ha errore "Cannot connect to database db:5432" invece di "db_v6"
# L'immagine usa ancora la vecchia variabile d'ambiente. # Ferma, rimuovi il container e riparti: docker stop superset_v6 docker rm superset_v6 cd ~/urbreath/superset docker compose -f docker-compose-v6.yml up -d superset_v6
Superset è partito ma i container si riavviano in loop
# Verifica quante volte è ripartito docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Restarts}}" # Leggi i log completi docker logs superset_v6 --tail 80
Rete Docker mancante dopo riavvio
# Se i container non trovano la rete superset_net_v6 docker network ls | grep superset_net_v6 # Se non esiste, ricrearla: docker network create superset_net_v6
