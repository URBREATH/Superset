Superset URBreath: comandi WSL e Docker

Riferimento operativo per compilare, avviare, fermare e controllare l'immagine custom di Superset 6.1.0.

Progetto: /mnt/c/Progetti/URBreath/Superset
Compose: docker-compose-v6.yml
Variabili locali: .env.v6
URL locale: http://localhost:17789

1. Preparazione del terminale WSL

Aprire WSL e portarsi nella root del progetto:

cd /mnt/c/Progetti/URBreath/Superset

È possibile definire una funzione abbreviata per il Compose. La funzione resta disponibile solo nel terminale WSL corrente. 

dc() {
  docker compose --env-file .env.v6 -f docker-compose-v6.yml "$@"
}

Verificare Docker e BuildKit:

docker --version
docker compose version
docker buildx version

2. Struttura della build custom

Il servizio superset_v6 usa il Dockerfile dei sorgenti Apache e il target finale urbreath. 

docker compose --env-file .env.v6 -f docker-compose-v6.yml build --pull superset_v6
Elemento Funzione
superset-source Contesto principale con sorgenti backend, frontend, requirements e Dockerfile Apache.
superset-source/Dockerfile Compila frontend, backend e target finale urbreath.
urbreath-config Contesto aggiuntivo con configurazione, logo, template e traduttore URBreath.
urbreath-superset:6.1.0-urbreath.1 Tag dell'immagine finale creata da Docker.

La build crea l'immagine ma non ricrea automaticamente il container. Dopo una nuova build occorre eseguire up.

3. Creare l'immagine Superset

Build normale

dc build --pull superset_v6

Build usando la cache disponibile

dc build superset_v6

Build completamente pulita

dc build --no-cache --pull superset_v6

Build e ricreazione del solo servizio Superset

dc up -d --no-deps --build superset_v6

Build diretta con Buildx e nuovo tag

Questo comando è utile per creare un tag diverso senza usare il tag definito attualmente nel Compose. 

docker buildx build \
  --file superset-source/Dockerfile \
  --target urbreath \
  --build-context urbreath-config=. \
  --tag urbreath-superset:6.1.0-urbreath.2 \
  --load \
  superset-source

L'opzione --load importa l'immagine nel Docker locale.

4. Creare una nuova versione dell'immagine

Per creare, ad esempio, la versione 6.1.0-urbreath.2 usando Compose:

  1. Modificare in docker-compose-v6.yml il valore di image.
  2. Verificare la configurazione.
  3. Compilare la nuova immagine.
  4. Ricreare il container.
dc config --quiet
dc build --pull superset_v6
dc up -d --no-deps --no-build superset_v6

Esempio di riga aggiornata:

image: urbreath-superset:6.1.0-urbreath.2

Il comando restart riavvia il vecchio container e non cambia immagine. Per usare un nuovo tag occorre ricreare il container con up.

5. Build degli altri componenti

Embedded App React

L'Embedded App usa il servizio embeddedsuperset_v6 del Compose principale. Il Dockerfile esegue la build React con Node e usa Nginx come runtime. 

dc build --pull embeddedsuperset_v6

Ricreare solo il container Embedded App:

dc up -d --no-deps --build embeddedsuperset_v6

Build di tutti i servizi che hanno un Dockerfile nel Compose v6:

dc build --pull

Questo comando compila Superset ed Embedded App. Database e Redis usano immagini predefinite e il componente Jobs usa un Compose separato.

URBreath Data Jobs

Jobs è un progetto Spring Boot separato. La build usa Maven e Java 21 definiti in urbreath-ds-jobs/Dockerfile. 

cd /mnt/c/Progetti/URBreath/Superset/urbreath-ds-jobs

dcjobs() {
  docker compose --env-file .env.jobs -f docker-compose-jobs.yml "$@"
}

dcjobs config --quiet
dcjobs build --pull urbreath-ds-jobs

Avviare il container Jobs:

dcjobs up -d --build urbreath-ds-jobs
dcjobs ps

Gestire Jobs:

dcjobs stop urbreath-ds-jobs
dcjobs start urbreath-ds-jobs
dcjobs restart urbreath-ds-jobs
dcjobs logs -f --tail=100 urbreath-ds-jobs

Per il funzionamento locale, Jobs utilizza il servizio PostgreSQL otherdb_v6. Se necessario, avviarlo dal progetto principale: 

cd /mnt/c/Progetti/URBreath/Superset
dc up -d otherdb_v6

Il file urbreath-ds-jobs/.env.jobs contiene credenziali e segreti: non inserirne i valori in documentazione o nei commit.

6. Avviare i servizi

Avviare database, Redis e Superset

dc up -d db_v6 redis_v6 superset_v6

Avviare tutto lo stack

dc up -d

Avviare solo l'Embedded App

dc up -d embeddedsuperset_v6

Controllare lo stato

dc ps
dc ps -a

7. Fermare e riavviare i servizi

Fermare solo Superset

dc stop superset_v6

Avviare un container fermo

dc start superset_v6

Riavviare Superset

dc restart superset_v6

Fermare Superset, PostgreSQL e Redis

dc stop superset_v6 db_v6 redis_v6

Fermare tutto lo stack senza eliminare i volumi

dc down
Attenzione: non usare dc down -v durante i test normali. L'opzione -v può eliminare i volumi PostgreSQL e superset_home.

8. Log e diagnostica

Log Superset in tempo reale

dc logs -f superset_v6

Ultime 100 righe

dc logs --tail=100 superset_v6

Log degli ultimi dieci minuti

dc logs --since=10m superset_v6

Health check del container

docker inspect --format '{{.State.Health.Status}}' superset_v6

Health endpoint HTTP

curl -sS -o /dev/null -w '%{http_code}\n' \
  http://localhost:17789/health

Utilizzo delle risorse

docker stats superset_v6

9. Verificare e ispezionare le immagini

Elenco delle immagini URBreath

docker image ls urbreath-superset

Dettagli di un'immagine

docker image inspect urbreath-superset:6.1.0-urbreath.1

Controllare la directory Superset nell'immagine

docker run --rm \
  --entrypoint /app/.venv/bin/python \
  urbreath-superset:6.1.0-urbreath.1 \
  -c "import superset; print(superset.__file__)"

Spazio usato da Docker

docker system df

10. Entrare nel container ed eseguire comandi Superset

Aprire una shell

dc exec superset_v6 bash

Visualizzare la versione Superset

dc exec superset_v6 superset version

Eseguire le migrazioni del database metadati

dc exec superset_v6 superset db upgrade

Reinizializzare Superset

dc exec superset_v6 superset init

Verificare i moduli custom

dc exec superset_v6 python -c \
  "import authlib, psycopg2, superset; print('runtime ok')"

11. Rete e volumi

Verificare la rete esterna

docker network inspect superset_net_v6 --format '{{.Name}}'

Creare la rete solo se non esiste

docker network inspect superset_net_v6 >/dev/null 2>&1 \
  || docker network create superset_net_v6

Elencare i volumi

docker volume ls

Ispezionare un volume

docker volume inspect superset_db_data_v6
docker volume inspect superset_superset_home_v6

I nomi effettivi dei volumi possono dipendere dal nome del progetto Compose. Usare sempre docker volume ls prima di eseguire operazioni sui volumi.

12. Rollback

Elencare i tag disponibili:

docker image ls urbreath-superset

Impostare nel Compose il tag precedente, ad esempio: 

image: urbreath-superset:6.1.0-urbreath.1

Ricreare solo Superset:

dc up -d --no-deps --no-build superset_v6

Il rollback dell'immagine non modifica automaticamente il database metadati; per questo è importante mantenere anche i backup.

13. Esportare e importare un'immagine

Esportare l'immagine in un file TAR

docker save \
  urbreath-superset:6.1.0-urbreath.1 \
  -o /mnt/c/Progetti/URBreath/Superset/urbreath-superset-6.1.0-urbreath.1.tar

Importare l'immagine su un altro Docker Engine

docker load \
  -i urbreath-superset-6.1.0-urbreath.1.tar

14. Comandi da usare con cautela

Questi comandi possono eliminare immagini, cache o volumi e non devono essere usati durante il normale ciclo di sviluppo senza aver verificato cosa verrà rimosso: 

docker system prune
docker system prune -a
docker volume prune
dc down -v

Prima di eventuali pulizie controllare sempre: 

docker system df
docker image ls
docker volume ls
docker ps -a
